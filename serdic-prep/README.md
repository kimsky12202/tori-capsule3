# 세르딕(SERDIC) 풀스택 엔지니어 입사 준비 — 마스터 플랜

> 채용공고 분석 + 내가 가진 것(토리 타임캡슐) 매핑 + 채워야 할 빈칸 + 주차별 학습 로드맵.
> **가우시안 스플래팅은 "신기술 관심도" 어필용 보너스이고, 채용의 본체는 풀스택 엔지니어다.**

---

## 0. 한 줄 요약

세르딕은 **"제조·산업 현장의 CCTV·센서·설비 데이터를 받아 → AI로 분석(작업현황/안전위험) → 웹 디지털 트윈에 실시간 시각화"** 하는 Hybrid SaaS를 만든다.
이번 채용은 그 서비스를 **현장에서 안정적으로 굴러가게 설계·구축하는 풀스택 엔지니어**를 뽑는 것.

→ **나의 전략: "토리 타임캡슐로 풀스택 기본기는 이미 증명했다. 거기에 회사가 강조한 실시간·대시보드·PostgreSQL·Vision 기초를 얹는다."**

---

## 1. 채용공고 요구사항 → 내 상태 매핑 (정확한 현재 위치)

### 자격요건 (필수)
| # | 요구사항 | 내 상태 | 근거 / 메모 |
|---|---|:---:|---|
| 1 | 3년+ AI서비스/풀스택 경험 **또는 준하는 실력** | ⚠️ | 신입이면 "준하는 실력"을 **프로젝트로** 증명해야 함 → 토리 + 이 레포 |
| 2 | 프론트+백엔드 웹 프레임워크로 설계·개발 | ✅ | Flutter(앱) + Go/PocketBase. **단, "웹" 프론트는 약함** → React 데모 1개 권장 |
| 3 | REST API, **WebSocket** 통신 구조 이해 | △ | REST는 Go로 직접 작성함. **WebSocket 경험 없음 → 1순위 학습** |
| 4 | **PostgreSQL/MySQL** 데이터 설계·쿼리 | △ | 지금은 SQLite(PocketBase). **PostgreSQL로 옮긴 경험 필요 → 2순위** |
| 5 | **Docker** 컨테이너 환경 | ✅ | docker-compose + Dockerfile 작성 경험 있음 |
| 6 | Linux, Git 개발·운영 | ✅ | Nginx 리버스 프록시 + Let's Encrypt 배포 문서까지 있음 |
| 7 | 시스템 구조 스스로 설계·구현 | ✅ | 토리 서버 라우트/마이그레이션 직접 설계 |
| 8 | 새 기술 빠르게 학습·응용 | ✅ | **가우시안 스플래팅 밑바닥 구현이 바로 이 증거** |

### 우대사항 (있으면 가점 — 차별화 포인트)
| 우대 | 내 상태 | 우선순위 |
|---|:---:|---|
| **Vision AI** (OpenCV, RTSP 스트리밍, 영상분석, DeepStream, TensorRT) | ❌ | ★★★ 회사 핵심. **OpenCV+RTSP 데모 하나면 강력** |
| **WebSocket, Redis, Message Queue** 실시간 서비스 | ❌ | ★★★ 자격요건과도 겹침 |
| **대시보드/관제/관리자 페이지** | ❌ | ★★★ 회사가 만드는 화면 그 자체 |
| **CCTV·IoT·설비 실시간 데이터 처리** | ❌ | ★★ Vision/실시간과 묶어서 |
| **CI/CD** 배포 자동화 | ❌ | ★★ GitHub Actions로 토리에 붙이면 끝 |
| 온프레미스/Hybrid SaaS 운영 | △ | ★ 개념 이해 위주 |
| AI 모델 추론 결과를 웹과 연동 | ❌ | ★★ Vision 데모에 자연히 포함됨 |
| 클라우드+온프레미스 아키텍처 설계 | △ | ★ 설명할 수 있을 정도면 OK |

### 결론: 채워야 할 5개 빈칸 (우선순위순)
1. **실시간 통신** — WebSocket (+ Redis pub/sub, 메시지 큐 개념)
2. **PostgreSQL** — SQLite에서 옮겨보기, 쿼리/인덱스/모델링
3. **대시보드/관제 화면** — 실시간 데이터를 차트·지도로 시각화
4. **Vision AI 기초** — OpenCV로 RTSP 영상 받아 간단 분석 → 웹 표시
5. **CI/CD** — GitHub Actions로 빌드·테스트·배포 자동화

> 이 5개를 **하나의 통합 데모**로 묶으면 = 미니 세르딕. (아래 6번 참고)

## 2. 회사 도메인 이해 (면접 대화용 키워드)

- **Hybrid SaaS**: 클라우드 SaaS + 고객사 현장(온프레미스) 혼합. 공장 데이터는 보안상 밖으로 못 빼는 경우가 많아서, **현장에 엣지(edge) 서버**를 두고 일부만 클라우드로 올림. → "왜 Hybrid인가?" 답할 수 있어야.
- **Vision AI**: CCTV 영상에서 객체/행동/이상을 탐지 (예: 안전모 미착용, 위험구역 침입, 작업 진행률).
- **Safety AI**: 위 결과로 안전 위험을 실시간 경보.
- **디지털 트윈**: 현장을 3D로 복제한 웹 화면. 센서/AI 이벤트를 그 위에 표시. ← **가우시안 스플래팅이 여기 들어감**
- **데이터 흐름**: `CCTV/센서 → (엣지)수집 → AI추론 → 메시지큐/Redis → 백엔드 → WebSocket → 웹 대시보드/3D트윈`. **이 한 줄 파이프라인을 외워라.** 회사가 하는 일 전체다.

## 3. 기술별 학습 가이드 (무엇을, 왜, 어떻게)

### 3-1. WebSocket (실시간) ★★★
- **왜**: 대시보드는 폴링이 아니라 "이벤트가 나면 즉시 화면에 뜨는" 푸시 구조. 회사 서비스의 심장.
- **개념**: HTTP(요청-응답, 단발) vs WebSocket(양방향, 연결 유지). SSE(서버→클라 단방향)와의 차이도.
- **핵심 질문 대비**: "수천 개 클라이언트 동시 연결이면? → 연결당 메모리, 수평 확장 시 Redis pub/sub로 서버 간 메시지 공유."
- **실습**: Go(gorilla/websocket 또는 표준 net/http)로 채팅/실시간 알림 서버 → 브라우저에서 받기.

### 3-2. PostgreSQL ★★★
- **왜**: 공고 명시. SQLite는 단일 파일·동시쓰기 약함 → 산업용은 PostgreSQL.
- **개념**: 정규화, 인덱스(B-tree), JOIN, 트랜잭션/ACID, EXPLAIN으로 쿼리 분석, 커넥션 풀.
- **시계열 보너스**: 센서 데이터 = 시계열 → TimescaleDB(PostgreSQL 확장) 한 번 들어보면 가점.
- **실습**: 토리 타임캡슐 스키마를 PostgreSQL로 옮기고 직접 쿼리 작성. (아래 6번)

### 3-3. 대시보드 / 관제 화면 ★★★
- **왜**: 회사가 파는 화면이 정확히 이것. "AI 추론 결과를 시각화하는 대시보드/모니터링/관리 기능".
- **개념**: 실시간 차트(시계열 라인/게이지), 상태 카드, 이벤트 로그 테이블, 지도/평면도 위 핀.
- **스택**: React + 차트 라이브러리(Recharts/Chart.js) + WebSocket. 또는 Grafana로 빠르게.
- **실습**: 3-1의 WebSocket 이벤트를 받아 실시간으로 갱신되는 대시보드.

### 3-4. Vision AI 기초 ★★★ (차별화 1순위)
- **왜**: 회사 이름이 "Vision AI". 여기서 데모 하나 있으면 다른 지원자와 확실히 갈림.
- **개념 단계**:
  1. **OpenCV**로 이미지/영상 읽기, 그리기.
  2. **RTSP** 스트림 받기 (CCTV 프로토콜). `cv2.VideoCapture("rtsp://...")`.
  3. 사전학습 모델로 **객체탐지**(YOLO 계열) — 직접 학습 말고 추론만.
  4. 추론 결과(박스/카운트)를 **백엔드로 → WebSocket → 대시보드**에 표시.
- **키워드만 알아도 가점**: NVIDIA DeepStream(다중 카메라 영상 파이프라인), TensorRT(추론 가속), ONNX.
- **실습**: 웹캠/샘플 영상 → YOLO로 사람 수 세기 → 실시간 대시보드에 카운트 표시.

### 3-5. Redis / Message Queue ★★
- **왜**: 실시간 데이터가 쏟아질 때 완충(buffer)·분산. 서버 여러 대 간 메시지 공유(pub/sub).
- **개념**: Redis(인메모리 캐시 + pub/sub), 메시지 큐(RabbitMQ/Kafka — 생산자/소비자 분리, 유실 방지).
- **언제 무엇**: "캐시·세션·실시간 브로드캐스트 → Redis. 대량 이벤트 안정 처리·재시도 → 메시지 큐."
- **실습**: WebSocket 서버 2대 + Redis pub/sub로 메시지 공유 (수평 확장 시연).

### 3-6. CI/CD ★★
- **왜**: "배포 자동화·버전 관리". 운영을 아는 엔지니어 = 회사가 원하는 "안정적 운영".
- **실습**: GitHub Actions — push하면 ① 테스트 ② Docker 빌드 ③ 배포. 토리 레포에 `.github/workflows` 추가.

### 3-7. 시스템 설계 / 아키텍처 ★★
- **왜**: "시스템을 스스로 설계·구현". 면접 단골(시스템 디자인).
- **개념**: 로드밸런서, 수평/수직 확장, 캐싱, DB 복제, 모놀리식 vs MSA, 온프레미스 vs 클라우드 트레이드오프.
- **연습**: "CCTV 100대에서 영상 받아 실시간 분석·표시하는 시스템을 설계해보세요"를 화이트보드로 그려보기.

## 4. 주차별 로드맵 (8주 예시 — 본인 속도로 조정)

> 매주 "**개념 학습 → 작은 실습 → 토리/통합데모에 반영**" 사이클.

| 주차 | 주제 | 산출물 |
|---|---|---|
| **1주** | PostgreSQL + 데이터 모델링 | 토리 스키마를 PostgreSQL로 이전, 쿼리 10개 작성 |
| **2주** | WebSocket 실시간 통신 (Go) | 실시간 알림 서버 + 브라우저 수신 데모 |
| **3주** | React + 대시보드 기초 | WebSocket 이벤트를 실시간 차트로 표시 |
| **4주** | Vision AI ① OpenCV + RTSP | 영상 스트림 읽어 프레임 처리·표시 |
| **5주** | Vision AI ② 객체탐지 추론 | YOLO로 사람/객체 카운트 → 백엔드 전송 |
| **6주** | 통합: 영상→AI→큐/Redis→WS→대시보드 | **미니 세르딕 데모 완성** (아래 6번) |
| **7주** | CI/CD + Docker 다듬기 | GitHub Actions 자동 빌드·배포 |
| **8주** | 시스템 설계 복습 + 면접 정리 + 가우시안 | 아키텍처 다이어그램, 예상질문 답변 녹음 |

> 시간이 없으면 **우선순위: 2주(WebSocket) → 3주(대시보드) → 4·5주(Vision)** 만 해도 공고의 핵심을 덮는다.

## 6. 통합 데모 제안 — "미니 세르딕" (가장 강력한 한 방)

> 빈칸 5개를 **하나의 프로젝트**로 묶으면, 공고의 거의 모든 항목을 한 번에 증명한다.

```
[샘플 CCTV 영상/웹캠]
        │  RTSP / 파일
        ▼
[Vision 서비스 (Python+OpenCV+YOLO)]   ← Vision AI, 영상분석
        │  탐지결과(JSON): 사람 수, 안전모 여부 등
        ▼
[Redis pub/sub 또는 메시지 큐]          ← Redis, MQ, 실시간 데이터 처리
        │
        ▼
[백엔드 (Go/FastAPI) + PostgreSQL]      ← REST, PostgreSQL, 데이터 저장
        │  WebSocket push
        ▼
[웹 대시보드 (React)]                    ← 대시보드/관제, 시각화
   - 실시간 인원/이벤트 카운트 차트
   - 이벤트 로그 테이블
   - (보너스) 평면도/3D 위 위치 핀  ← 여기에 가우시안 트윈 연결 가능
        │
   전체를 Docker Compose로 구동          ← Docker
   GitHub Actions로 빌드·배포            ← CI/CD
```

이거 하나면 면접에서: *"공고를 보고 회사가 만드는 파이프라인을 축소판으로 직접 구현해봤습니다"* 라고 말할 수 있다. **합격 확률을 가장 크게 올리는 단일 프로젝트.**
